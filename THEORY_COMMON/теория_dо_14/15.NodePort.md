NodePort — это один из способов настройки сетевой службы (Service) в [Kubernetes](https://kubernetes.io/docs/concepts/services-networking/service/), который позволяет открыть определенный порт на всех узлах (нодах) кластера для приема внешнего трафика. Любой запрос, пришедший на этот порт на IP-адрес любой ноды, автоматически перенаправляется на внутренние поды приложения. [1, 2, 3] 
## Как это работает
Когда вы создаете NodePort, Kubernetes делает следующее: [4, 5] 

   1. Выделяет статический порт (по умолчанию в диапазоне от 30000 до 32767).
   2. Настраивает прокси-слой (kube-proxy) на каждой ноде кластера, чтобы тот слушал этот порт.
   3. Перенаправляет весь входящий на этот порт трафик на внутренний IP-адрес сервиса (ClusterIP), который затем балансирует его между рабочими подами. [2, 6, 7, 8, 9] 

Таким образом, ваше приложение становится доступно по адресу http://<IP_любой_ноды>:<выделенный_NodePort>. [8] 
------------------------------
## Различие между тремя типами портов
Для правильной настройки NodePort важно различать три параметра: [10, 11] 

* nodePort: Внешний порт на самих серверах (нодах), куда обращаются пользователи (например, 30007).
* port: Внутренний порт самого сервиса Kubernetes внутри кластера.
* targetPort: Порт внутри контейнера (в поде), на котором непосредственно запущено ваше приложение. [3, 10, 12]

## Пример YAML-манифеста
Ниже представлен классический пример конфигурации сервиса типа NodePort: [3, 13] 

apiVersion: v1kind: Servicemetadata:
  name: web-servicespec:
  type: NodePort
  selector:
    app: my-web-app  # Трафик пойдет на поды с этой меткой
  ports:
    - protocol: TCP
      port: 80         # Внутренний порт сервиса
      targetPort: 8080 # Порт внутри контейнера
      nodePort: 30007  # Внешний порт ноды (необязательно, можно оставить на автовыбор)

## Плюсы и минусы использования NodePort

* Плюсы:
* Простота: Самый элементарный способ вывести приложение наружу без настройки сторонних облачных решений.
   * Универсальность: Работает на любой инфраструктуре, включая локальные кластеры (Minikube, Kind, bare-metal). [2, 11, 13, 14, 15] 
* Минусы:
* Ограничение портов: Можно использовать только диапазон 30000–32767 (нельзя напрямую открыть стандартные порты 80 или 443).
   * Один сервис — один порт: Для каждого нового приложения придется выделять и запоминать новый случайный порт.
   * Проблемы безопасности и маршрутизации: IP-адреса нод могут меняться, а открытие портов наружу напрямую увеличивает площадь атаки, требуя ручной настройки файрволов. [2, 16, 17] 
* 

## Когда использовать?
Обычно NodePort используют для разработки, демонстраций или тестирования. Для постоянного промышленного использования (Production) поверх NodePort обычно настраивают полноценный [Ingress-контроллер](https://dev.to/nk_sk_6f24fdd730188b284bf/understanding-nodeport-port-and-targetport-in-kubernetes-services-1b66) или сервис типа [LoadBalancer](https://kubernetes.io/docs/tutorials/kubernetes-basics/expose/expose-intro/). [2, 10, 14] 
Если вы хотите развернуть сервис, уточните: вам нужно настроить маршрутизацию для веб-сайта (HTTP/HTTPS) или вы открываете порт для других протоколов (базы данных, брокеры сообщений)? Напишите, и мы подберем оптимальный тип манифеста. [5, 18, 19]
