Хороший вопрос — это базовое понятие, и без него непонятно, что мы вообще делаем. Объясню по-простому.

## Аналогия

Представь, что **Docker-образ** — это посылка с готовым приложением. Внутри лежит код, библиотеки, всё нужное для запуска.

**Registry** (по-русски «реестр», но все говорят «реджистри» или «регистри») — это **склад посылок**. Туда сборщик кладёт готовые образы, оттуда сервер их забирает, чтобы запустить.

```
[Kaniko/buildctl собрал образ]
        ↓
   [REGISTRY] ← склад
        ↓
[Kubernetes забирает и запускает]
```

## Зачем он нужен

Когда Kubernetes хочет запустить твой `frontend` — он должен где-то взять образ `frontend:abc123`. Он не умеет «забрать с диска того, кто его собрал». Он умеет только **скачать из registry** по сети.

Поэтому **обязательно нужно**:
1. Кто-то собирает образ (Kaniko, buildkit, docker build).
2. Сборщик **пушит** (загружает) образ в registry.
3. Kubernetes **пуллит** (скачивает) образ из registry, когда нужно запустить под.

Без registry эта цепочка рвётся.

## Какие бывают registry

| Registry | Где он | Кто хозяин | Что хранит |
|---|---|---|---|
| **Docker Hub** | `docker.io` | компания Docker | публичные образы (busybox, nginx, postgres) и твои личные |
| **GitHub Container Registry** | `ghcr.io` | GitHub | образы рядом с твоим кодом на гитхабе |
| **Google Artifact Registry** | `*.pkg.dev` | Google Cloud | образы для GKE |
| **Локальный registry** | `10.174.8.95:30500` (у тебя) | ты | образы внутри твоего кластера |

## Что у тебя в проекте

Раньше план был — пушить в **Docker Hub** (`docker.io/zangievmovsar/...`). Но потом мы перешли на **локальный registry в твоём кластере** — это образ `registry:2`, который крутится в Kubernetes и слушает порт `30500` на ноде `10.174.8.95`.

Когда мы делали smoke-тест и видели:
```
{"repositories":["smoketest"]}
```

Это значит «локальный склад опросили, и он сказал: у меня лежит один образ — smoketest». То есть твой склад работает.

## Почему перешли с Docker Hub на локальный

Скорее всего по одной из причин:
- Docker Hub режет по rate-limit (бесплатные аккаунты могут пушить/пуллить ограниченное число раз в час).
- Локальный быстрее — образы не уходят в интернет и обратно, лежат рядом с кластером.
- Не нужно прокидывать токены наружу.
- В школьном окружении интернет может быть медленным или нестабильным.

## Что важно знать про твой registry

1. **Адрес снаружи кластера:** `10.174.8.95:30500` (через NodePort).
2. **Адрес изнутри кластера:** обычно `registry.<namespace>.svc.cluster.local:5000` или подобный.
3. **HTTP без TLS** — поэтому в командах фигурирует `registry.insecure=true` (типа «не ругайся, что нет HTTPS»).
4. **Без аутентификации** — кто угодно в твоей сети может пушить и пуллить. Для школьного проекта это нормально.

## В контексте твоего пайплайна

Цепочка теперь такая:
```
git push → GitLab Runner → создаёт под с buildctl
                                ↓
                       buildctl собирает образ
                                ↓
                       пушит в 10.174.8.95:30500/frontend:abc123
                                ↓
                       helm upgrade в staging
                                ↓
                       Kubernetes пуллит образ из 10.174.8.95:30500
                                ↓
                       поднимает под с frontend
```

Registry — **середина** этой цепочки. Без него образ собран, но никто его не увидит.
