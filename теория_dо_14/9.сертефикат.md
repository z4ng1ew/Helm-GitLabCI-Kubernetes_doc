## Что проверим

В ДО13 ты ставил `cert-manager` для TLS-сертификатов (Let's Encrypt). Покажи мне:

```sh
# 1. Есть ли cert-manager в кластере
kubectl get pods -n cert-manager 2>/dev/null || echo "cert-manager не установлен"

# 2. Есть ли ClusterIssuer (тот, что выписывает сертификаты)
kubectl get clusterissuer 2>/dev/null || echo "ClusterIssuer нет"

# 3. Какие сертификаты есть в staging
kubectl get certificate -n staging 2>/dev/null
kubectl get secret -n staging | grep tls

# 4. Что в ingress staging сейчас
kubectl get ingress -n staging -o yaml | grep -A 3 "tls:\|host:"
```

## Что важно понимать про nip.io и TLS

У тебя домен `bank.10.174.8.95.nip.io`. Это **публичный DNS**, который резолвится в твой **внутренний IP** (10.174.8.95). 

**Проблема:** Let's Encrypt не выпустит сертификат на nip.io с приватным IP, потому что:
1. ACME-challenge (HTTP-01) требует, чтобы Let's Encrypt сам мог сходить на твой адрес из интернета. К приватному IP `10.174.8.95` он не достучится.
2. nip.io в принципе работает для тестов, но боевые сертификаты на него не выписывают.

Так что у тебя скорее всего:
- Либо **самоподписанный** сертификат (cert-manager выпустил сам через `selfsigned-issuer`).
- Либо **никакого TLS** — всё ходит по `http://`.
