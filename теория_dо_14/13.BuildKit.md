BuildKit — это современный, быстрый и эффективный инструментарий для сборки контейнеров, разработанный в рамках проекта Moby Project (GitHub) компанией Docker. Он полностью заменил собой устаревший стандартный движок docker build.Если вы используете современные версии Docker, BuildKit уже включен по умолчанию или вызывается через плагин командной строки Docker Buildx.🚀 Главные преимущества BuildKitПараллельное выполнение стадий: Движок автоматически анализирует граф зависимостей вашей сборки и запускает независимые стадии (stages) параллельно.Пропуск неиспользуемых этапов: Если в многоэтапной сборке (multi-stage build) результат какой-то стадии не используется в финальном образе, BuildKit вообще не будет её выполнять.Продвинутое кэширование: Поддерживает удаленный импорт/экспорт кэша (registry, S3, inline), что критически важно для быстрых сборок в CI/CD (GitLab, GitHub Actions).Безопасная работа с секретами: Позволяет безопасно пробрасывать секреты (--secret) и SSH-ключи (--ssh) на этапе сборки без сохранения их в истории слоев готового образа.Режим Rootless: Возможность сборки образов без прав суперпользователя (root), что значительно повышает безопасность контейнерных сред.🛠 Ключевые возможности в DockerfileBuildKit открывает доступ к расширенному синтаксису Dockerfile с помощью директивы # syntax=docker/dockerfile:1 в самом начале файла:Кэширование пакетов (Mount Cache):Ускоряет повторные сборки, сохраняя кэш пакетных менеджеров (npm, pip, apt) между сборками:dockerfileRUN --mount=type=cache,target=/root/.npm npm install
Используйте код с осторожностью.Безопасные секреты:Использование токенов без риска утечки:dockerfileRUN --mount=type=secret,id=my_token ./deploy.sh
Используйте код с осторожностью.💻 Как начать работу1. В Docker DesktopВ современных версиях Docker Desktop инструментарий BuildKit интегрирован из коробки. Чтобы использовать его на полную мощность, запускайте сборки через утилиту buildx:bashdocker buildx build -t my-image:latest .
Используйте код с осторожностью.2. В Linux (без Docker Desktop)Если вы используете классический Docker Engine в Linux, вы можете временно включить BuildKit с помощью переменной окружения:bashDOCKER_BUILDKIT=1 docker build -t my-image:latest .
Используйте код с осторожностью.Или включить его глобально в конфигурационном файле /etc/docker/daemon.json:json{
  "features": {
    "buildkit": true
  }
}
Используйте код с осторожностью.3. Экспорт кэша в CI/CD (Пример)Пример команды для сборки образа в пайплайне с сохранением кэша в удаленный репозиторий:bashdocker buildx build --push \
  --cache-to type=registry,ref=myregistry/cache-image:latest \
  --cache-from type=registry,ref=myregistry/cache-image:latest \
  -t myapp:latest .
Используйте код с осторожностью.Какую именно задачу вы хотите решить с помощью BuildKit?
