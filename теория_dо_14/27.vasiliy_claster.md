## Шаг 1 — настроить твой kubectl на его кластер (с твоей машины)

Чтобы управлять кластером не по ssh, а со своей машины (удобнее). Забери kubeconfig с мастера. **На мастере** (ты сейчас там) посмотри конфиг:

```sh
sudo cat /etc/rancher/k3s/k3s.yaml
```

Там будет YAML с `server: https://127.0.0.1:6443`. Скопируй его содержимое себе, но **поменяй** `127.0.0.1` на внешний IP мастера `185.50.202.99`.

Удобнее одной командой — **на мастере** сгенерь готовый конфиг с правильным IP:

```sh
sudo sed 's/127.0.0.1/185.50.202.99/' /etc/rancher/k3s/k3s.yaml > /tmp/do14-vps.yaml
cat /tmp/do14-vps.yaml
```

Вывод (это kubeconfig, в нём сертификаты-ключи — обращайся как с секретом) скопируй. Потом **на своей машине** сохрани его и проверь доступ:

```sh
# на ТВОЕЙ машине
mkdir -p ~/.kube
# вставь содержимое в файл (через nano/редактор или scp — см. ниже)
nano ~/.kube/do14-vps-config     # вставь скопированное, сохрани

export KUBECONFIG=~/.kube/do14-vps-config
kubectl get nodes
```

Если `kubectl get nodes` с твоей машины покажет 3 ноды — управление настроено, по ssh больше лазить не надо.

> Можно и через scp, без копипасты:
> ```sh
> # на ТВОЕЙ машине
> scp -i ~/"Рабочий стол/do_14 (2)/master" master@185.50.202.99:/tmp/do14-vps.yaml ~/.kube/do14-vps-config
> ```
> (сначала на мастере создай `/tmp/do14-vps.yaml` командой sed выше, и дай к нему доступ: `sudo chmod 644 /tmp/do14-vps.yaml`).

> Проверь порт **6443** (k3s API) снаружи — он должен быть открыт, иначе с твоей машины не достучишься:
> ```sh
> # на твоей машине
> timeout 3 bash -c "cat < /dev/null > /dev/tcp/185.50.202.99/6443" && echo "6443 открыт" || echo "6443 закрыт"
> ```
> Если закрыт — будем управлять по ssh с мастера (тоже рабочий вариант), или попросишь Василия открыть порт.
